# Career Ontology

이 페이지는 내부 Obsidian vault에서 관리하는 온톨로지/메모를 바탕으로 만든 공개용 요약본입니다.

## Core Positioning
- AI를 활용해 낯선 도메인의 문제를 빠르게 구조화하고 구현까지 연결하는 실전형 엔지니어
- 프론트엔드·백엔드·인프라를 하나의 흐름으로 연결해 운영 가능한 결과로 수렴
- 빠른 구현만이 아니라 정확성, 구조화, 복잡도 통제를 함께 중시

## Drivers
- 성장 60 / 수익 40
- 빠른 성장과 다양한 경험 우선
- 실전 문제 해결 중심

## Evidence Pattern
프로젝트와 작업 기록은 가능하면 아래 구조로 설명합니다.
1. 상황
2. 판단
3. 구현
4. 결과

## Evidence Examples
- Ansible 기반 인프라 자동화
- AI 기반 프로젝트 부트스트랩 (SSE/WebSocket/Swagger/React hook/MSW)
- LangGraph agent 구조 설계

## Market Perception
- 시장에서는 일반 개발자로 보이기 쉬우나 실제 강점은 AI leverage + 구조화 + end-to-end 연결 능력
- 현재 병목은 구현 역량 부족보다 포트폴리오, 자기설명, 신뢰 신호 정리 부족에 가까움

## Public / Private Split

# Career Ontology

## Why this matters
- 사용자는 단순 기술 목록이 아니라 **자신을 설명하는 구조**를 갖고 싶어 한다.
- 포트폴리오의 병목은 구현 능력 자체보다 **자기설명, 신뢰 신호, evidence 구조화**에 있다.
- 따라서 온톨로지는 메모가 아니라 이후 소개 문구, 프로젝트 카드, 협업 설명을 지탱하는 상위 모델이다.

## Core ontology layers
- **Identity**: AI를 활용해 낯선 도메인의 문제를 빠르게 구조화하고 실제 구현까지 연결하는 실전형 엔지니어
- **Drivers**: 성장 60 / 수익 40, 빠른 성장과 다양한 경험 우선
- **Preferences**: UI 미세 수정 선호 낮음, 과한 아키텍처 회피, 구조화/정확성/효율성 선호
- **Capabilities**: 프론트엔드·백엔드·인프라를 연결해 운영 가능한 시스템으로 수렴시키는 능력
- **Evidence**: Ansible 자동화, AI 기반 프로젝트 부트스트랩, LangGraph/agent 설계
- **Market perception**: 시장에서는 일반 개발자로 보이기 쉬우나 실제 강점은 AI leverage + 구조화 + end-to-end 연결 능력
- **Decision rules**: 문제를 구조화하고, 복잡도를 통제하며, 재사용 가능한 흐름으로 정리하는 방향을 우선

## Repeated patterns
- 설명 프레임은 **상황 → 판단 → 구현 → 결과**가 가장 재사용성이 높다.
- GitHub commit/repo는 raw evidence이고, 사람에게 보여줄 때는 해석된 evidence로 다시 써야 한다.
- AMOS 관련 프로젝트를 중심으로 evidence를 배치하는 것이 현재 포트폴리오 방향과 맞다.
- Honcho/메모리 저장은 불안정할 수 있으므로 파일 기반 구조화 저장이 우선이다.

## Durable conclusions
- 온톨로지는 포트폴리오 부가자료가 아니라 자기설명 엔진이다.
- 포트폴리오의 headline, about, collaboration, project cards는 이 온톨로지에서 파생되어야 한다.
- 공개 사이트에는 선별 공개본을 두고, 전체 작업 기억은 Obsidian vault에 두는 이중 구조가 적절하다.

## Vault Memory Excerpt
# Portfolio Ontology

## Durable fact
- 사용자의 커리어 설명은 기술 나열보다 **문제 구조화 → 판단 → 구현 → 결과** 프레임으로 조직될 때 가장 강하다.
- 핵심 포지셔닝은 **AI leverage + 낯선 도메인 빠른 흡수 + end-to-end 구현 + 복잡도 통제**다.
- 포트폴리오 병목은 구현 역량 부족이 아니라 evidence 정리와 신뢰 신호 번역 부족이다.

## Why it matters
- 소개 문구, 프로젝트 상세, 협업 방식 설명, 면접 답변에 같은 프레임을 재사용할 수 있다.
- AMOS 중심 프로젝트 큐레이션 방향과도 정합적이다.

## Boundaries
- 모든 프로젝트를 같은 깊이로 정리할 필요는 없다.
- 공개본에는 민감한 내부 맥락 대신 evidence와 해석만 남긴다.
